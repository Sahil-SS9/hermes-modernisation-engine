# Threat model and operational boundaries

Status: engineering preview, not general execution acceptance.

Trust the OS kernel, rootless Docker daemon/CLI, explicitly pinned image contents, external operator, enrolled approving owner and protected authority ledger. Do not trust repository programs/config/instructions, model text, imported reports, executable build hooks, caller supplied flags or a candidate's self-reported JUnit/output. Docker shares a host kernel; no VM-grade isolation is claimed.

Repository-code workloads are network-disabled containers with a read-only source bind, read-only root, no host home or Docker socket, no inherited provider environment, non-root uid, all capabilities dropped, no-new-privileges, process/memory/CPU/file-descriptor limits and bounded tmpfs. The trusted host control plane must have Docker access to create/start/kill/inspect; it is not a repository-code workload and is never exported or mounted in candidates. Image preparation with network is separate from running source code. Unknown images/privileges/mount roots refuse.

Execution uses external Ed25519 verification with a durable one-use claim. Public keys and canonical grants are nonsecret; only the owner holds the real private key. Fixture keys are exclusively for test mechanisms and cannot authorise real jobs. Claims bind actor, profile, attempt, source/candidate/oracle/environment/image, argv, read/write roots, network and resource limits. Phase and executor-code identity are bound through environment identity. No sign/approve endpoint exists in the consumer package. A public key's encoding alone is not enrolled possession proof.

The external executor freezes bounded no-follow source bytes, modes and empty directory identities; excluded generated/VCS directories are explicit. Source signatures are checked again during and after capture. Changed identities refuse; stale evidence remains visible. Snapshot v2 includes directory state and cannot reuse legacy file-only approval digests. Unsupported credential patterns, hostile concurrent writers able to replace private operator state, source mount race attacks by a compromised owner and Docker/kernel exploits remain outside the assurance claim. Protected source copies should be operator-owned and inaccessible to candidate writers.

Create/start operations use only exact validated argv and generated runtime identities; signed argv values such as --rm are preserved as payload, not filtered globally. Output is collected incrementally with a real deadline and byte cap. Timeout/overflow triggers kill; forced removal destroys the whole container process namespace, including descendants. Removal is read back and a failed/ambiguous cleanup refuses evidence acceptance. An exited process/zero code is never inferred to mean test success. A process receipt remains observed-process-only and NOT_PROVEN until an independent protected evaluator accepts the correct tests/cases.

Crash boundary: attempted source snapshots and one-use claims persist. No blind resume exists. A daemon-created container may survive operator process loss; exact attempt/container names and IDs are retained for explicit recovery. On an ambiguous create crash, deterministic names permit inspection. Automated reattachment, lease/fencing/recovery transitions are NOT complete; native run/resume stay disabled. Do not treat source snapshots or successful fixture tests as complete M0/M2 acceptance.

Storage uses owner-only profile-private data roots, no source overlap, no-follow file opens, transactional SQLite updates, idempotency keys and optimistic revisions. Queries open SQLite read-only and do not create job state. Schema v1-to-v2 upgrade has a private consistent backup before atomic upgrade. Existing backup collision/interrupted upgrade refuses for operator recovery rather than overwriting evidence. SQLite FULL does not claim cross-machine availability or protection against a malicious trusted writer. Source read-only assessment can save private metadata; report/status/compare cannot launch code/models. Profile path lookup follows the active host profile per call.

Reports escape repository text, have no scripts or outbound assets, and include a restrictive CSP. Private inventories can reveal source paths, names and code structure. Private reports/receipts/grants are NOT public-safe by default. No generic secret scrubber or complete credential detector is claimed; unknown secrets must never be sent to a model or published. Model egress, automatic provider calls, telemetry, background rewrites and live installation remain disabled.

Supported evidence: real Linux rootless Docker controls, native CLI/plugin-loader/tool-registry/registered slash handler on a specifically patched sandbox host. Real gateway slash dispatch and macOS/Windows execution are UNVERIFIED/UNSUPPORTED. There is no deployment, independent implementation sign-off, public licence grant or release approval.
